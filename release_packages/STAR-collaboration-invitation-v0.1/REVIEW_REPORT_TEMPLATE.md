# Bounded collaboration review report

Copy this template into a **new** dated report or issue comment. Do not fill
unknowns with plausible values; write `unverified`, `not run` or `not applicable`
with a reason. Public reports must contain no credentials, private keys,
personal data or vulnerability exploit details.

- Task ID and review question:
- Reviewer name/handle, relevant expertise, affiliation if volunteered:
- Independence: relationship to authors, prior implementation/data access,
  conflicts, assistance/tools used, and who can authenticate this statement:
- Exact repository URL, baseline commit, reviewed commit and PR head:
- Qualified Claim_ID / Experiment_ID / Dataset_ID / Parameter_Set_ID / Null_ID
  or theory-search/obstruction ID (explain inapplicable fields):
- Frozen protocol/version and governing Charter hash:
- Input paths, publisher/version/URL, license/acknowledgment requirements,
  actual byte sizes and SHA-256 values; identify any LFS pointers separately:
- Selection/exclusion, preprocessing, matching, coordinate/units/sign conventions:
- Environment, dependency versions/locks, OS, CPU, random algorithm and seeds:
- Work actually done (static inspection / saved-package verification / synthetic
  software test / independent proof review / separately authorized rerun):
- Commands, start/end UTC, exit statuses and complete logs or durable log hashes:
- Expected checks/tolerances and how they were fixed before examining outcomes:
- Actual observations, full outcomes, discrepancies, counterexamples and failed
  checks; link new immutable outputs/manifests without overwriting prior records:
- Checks skipped/unavailable, why, and what additional evidence would resolve them:
- Precise supported statement and stronger statements that remain unsupported:
- Review disposition: verified within stated scope / discrepancy / inconclusive /
  ineligible; use the project's scientific outcome taxonomy only when its gates
  actually apply:
- Requested next step, proposed changed paths and separate authorization needs:
- Citation list: exact software revisions, artifact-specific archive identifiers,
  original catalog/method sources, access dates and corrections:
- Human reviewer attestation and date (if actually provided; no invented signature):

An author cannot self-certify independent review. An automated test receipt is
not a human signature, independent proof or scientific endorsement. Any proposed
registry/status transition requires a separate accountable review; posting this
report does not change flags.
